# YumeShelf

一个更懂你的游戏盒子。YumeShelf 是 Windows 本地游戏库与 Yume 智能体的统一应用，当前版本 0.3.0-preview.1（测试版，尚未完成真实模型与干净系统发行验收）。

当前远程仓库：[luyu275573-cpu/YumeShelf](https://github.com/luyu275573-cpu/YumeShelf)，默认分支 `master`。2026-09-22 从旧账号迁移既有 Git 历史，迁移范围和本地未提交工作的状态见[开发日志](docs/development-log.md#2026-09-22github-仓库迁移)。

## 当前能力

- 正式名称 YumeShelf，采用黑白灰圆角 YS 字母图标；启动时先显示应用名，再显示“一个更懂你的游戏盒子...”，约2.3秒自动进入游戏库，可点击按钮或按Enter/Esc跳过，遵循系统动画设置。
- 添加本地 `.exe` 游戏。
- 保存游戏目录、启动文件和工作目录。
- 搜索标题、引擎、游戏类型、标签和简介。
- 全部游戏、最近游玩、收藏筛选。
- 封面网格和紧凑列表视图切换。
- 大游戏库每页最多显示 60 项，搜索和排序覆盖全部条目。
- 启动游戏并监听进程退出。
- 记录最近游玩时间和累计游玩时长。
- 本地 JSON 原子保存、上一版备份、损坏数据只读恢复、单实例和保存冲突保护。
- 编辑标题、引擎、年份/日期、游戏类型、工作目录、启动参数、封面和简介；游戏移动后可重新选择 EXE，保留游玩记录。
- 主窗口内导航：游戏库、设置和 AI 助手在右侧切页，左侧固定；支持上下过渡，切换时保留草稿和会话。
- 分类设置页：应用美化、AI 检索、页面分栏；保存或取消后留在当前页。
- 统一操作结果提示：设置保存、游戏管理和 API 测试等有明确反馈；游戏库写入失败保留修改并可重新保存。
- AI 基础问答：自配兼容 API 地址、Key 和模型，支持模型语义路由、固定短拒答及流式正文；停止/异常保留已收到的内容和问题，支持原消息重试。新增有限工具调度，支持 VNDB 作品检索、资料审核及手动导出。
- AI 看图识别：选择图片或粘贴截图、预览/移除后发送，尝试识别 Galgame/视觉小说或分析相关报错；支持可选识图模型，不确定时说明依据。需服务支持图片输入，识别准确率取决于模型和图片。
- AI 游戏库管家：对话自动定位作品，查询资料和封面，在同一修改卡片选择并确认保存，支持整次撤销；发送本机文件夹/EXE 路径可扫描并确认入库。
- 库查询支持收藏、是否有游玩记录、运行中、启动文件缺失/不可访问等组合条件；依据当前本地快照，不向模型上传完整路径或原始游玩统计。
- 本机加密保存最近文字会话和输入草稿；同配置恢复有限上下文，图片及待确认操作不跨重启恢复，新对话清除旧文字记录。
- 背景图片预览、页面透明度、高斯模糊和简化/完整布局；确认后保存，取消丢弃更改。

## 开发环境

- Windows 10/11 x64
- .NET 8 SDK
- Visual Studio 2022（推荐）或 Rider

## 打开和运行

```powershell
dotnet restore .\YumeShelf.sln
dotnet build .\YumeShelf.sln
dotnet run --project .\src\YumeShelf\YumeShelf.csproj
```

也可以使用项目脚本：

```powershell
.\scripts\run.ps1
```

本机已安装 .NET 8 SDK。构建和运行脚本在 PATH 未刷新时会查找标准安装位置，验证记录见 `docs/development-log.md`。

统一验证（Release 构建、设置/导航/反馈回归、可靠性与模拟 AI 回归、发布资源检查；隔离数据，不调用真实 AI）：

```powershell
.\scripts\check.ps1
```

## 数据位置

添加游戏支持自动搜索和手动添加。自动搜索默认“视觉小说优先”，新增“扩展游戏扫描”用于查找 RPG Maker、WOLF RPG、Unity、GameMaker 等游戏；扩展候选显示依据并默认不勾选，核对后确认入库。视觉小说规则补充 NScripter/ONScripter、RealLive、Siglus、Artemis、YU-RIS，保留 Ren'Py、BGI、KiriKiri、TyranoScript 与自定义 BIN 结构。模式切换清空旧结果，支持重新扫描。

引擎识别不等于玩法分类：ACT、SLG、RPG 标签不会自动推断，普通 NW.js 程序不会仅凭运行框架入选。扫描有深度、数量、文件头读取与时间限制，达到限制或资源不可读时明确提示“扫描不完整”。具体规则、版本边界和测试范围见 [游戏扫描说明](docs/game-scanning.md)。

```text
%LOCALAPPDATA%\YumeShelf\library.json
%LOCALAPPDATA%\YumeShelf\settings.json
```

游戏本体文件不会被复制、移动或删除。删除游戏条目只会删除启动器中的记录。

损坏或无法完整读取游戏库时暂停写入，提示中可打开数据目录或确认恢复当前可读列表。恢复前保留原文件为 `library.json.recovery-*.json`，正常保存保留 `library.json.bak`。失败修改可重试，关闭应用前需处理待保存内容。诊断日志位于同目录 `logs/`，只记操作分类与异常类型，不记录 Key 或对话正文。

云端 AI 地址必须为 HTTPS，本机回环服务允许 HTTP。修改服务来源后需重新填写 Key。问题最多 6000 字符，单次等待默认 60 秒（5–120）、整任务默认 180 秒（5–600）；失败、取消或截断不冒充成功。组合任务保留已完成结果并说明未完成部分，原问题保留。

检查产物在 `.runtime/checks/`，依赖框架的发布目录在 `.runtime/publish/`（需 .NET 8 Desktop Runtime）。本项目的回归是控制台程序，单独执行 `dotnet test` 不会运行这些检查。

分发测试包：门禁通过后执行 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/package.ps1`，生成Windows x64自包含ZIP、文件清单、SHA-256和无用户数据的启动自检报告。无需测试者安装.NET；解压可直接运行，也可执行包内Install.ps1复制到当前用户目录并创建桌面快捷方式。[安装、升级与卸载说明](docs/release-guide.md)说明当前测试包边界。真实AI验收使用 [YumeTestV1](YumeTestV1.md)，共54项场景，开发者不代用真实Key测试。

2026-09-24验证状态：411项可靠性回归通过；0.3.0-preview.1自包含包已完成本机隔离安装、文件完整性、快捷方式和重复安装保护验证。真实模型与干净Windows系统的人工验收仍待完成，详见[发行验证记录](docs/release-guide.md#2026-09-24-验证记录)。测试产物保存在本地`.runtime/`，不随源码上传。

识图使用方法：在“设置 → AI 检索”填写同一 API 服务提供的可选视觉模型，留空沿用对话模型。可主动点击“测试视觉能力”验证内置数字图，文字测试成功不代表识图可用。回到 AI 助手选择 PNG/JPG/BMP 或粘贴截图（支持微信多格式剪贴板、Ctrl+V），可不填问题直接发送。图片仅随首个视觉请求上传，后续对话模型复用文字线索；每轮最多 6 次模型/4 次工具调用，无自动付费重试。

图片源文件限制 32 MiB/4000 万像素，缩至长边最多 1600 像素、PNG 最多 4 MiB；只预览不联网，元数据剥离后上传，日志不记录图片。全透明/损坏图片提前拒绝。真实服务兼容与作品识别准确率仍须用用户选择的模型验证。

游戏库协作：直接说“帮我更新樱之诗的简介、日期和封面”，Yume 根据作品名、对话和主界面选中项自行查库定位；有版本歧义时澄清，不要求手动关联。核对来源、字段和图片后一次确认保存，可撤销最近一次完整卡片修改。只读、冲突、目标删除或保存失败均保留原资料。摘要不含启动路径、参数或统计；用户主动在问题中输入的路径会随消息发给所配置的模型。

本地查询：直接问“我现在的库里有几个游戏”或“我的游戏库有哪些游戏”，无图片时读取当前库并立即回答，无需API配置、不产生模型用量。复杂筛选由模型调用专用查询工具，程序按真实记录计数/分页；不能把前5个搜索候选当成完整游戏库。读库异常或存在未保存修改时说明状态，不报告虚假的0项。

非快捷执行任务先独立核对任务类型，通常比原流程多一次短模型请求，仍受6次总预算限制；已读本地详情由程序直接显示。组合任务完成后逐项反馈，普通追问保留待确认结果与选择。每类最多一份待确认结果，先保存或放弃才能替换同类内容；可选字段支持明确清空。自然语言意图仍依赖模型，模拟回归不代表真实模型零误判。

发送任务后按需查询 VNDB 官方公开 API，无需额外 Key 或勾选联网；显示实际来源。复合补全一次取得文字与封面，单来源自动准备，多来源先选版本。简介保留来源原文，未知引擎/游戏类型/标签保持原值；用户明确提供新值时也可生成修改草稿。当前不是通用网页搜索或反向搜图。资料草稿可导出 Markdown/安全 HTML。

封面属于同一张修改卡，无独立封面功能面板。只覆盖 VNDB 普通封面，不保证每个作品有结果。预览超时保留文字结果；确认后原图保存在 `%LOCALAPPDATA%\YumeShelf\Covers\`，不改游戏目录；文字和封面一起成功或回滚。重启保留已保存内容，撤销仅本次会话有效。

对话入库：发送 `扫描并添加这个文件夹："G:\Games"`，或明确的 EXE 路径。Yume 调用现有识别规则、显示候选并等待确认，再复用持久保存与去重流程。只能扫描当前消息给出的本机路径，不扩大目录、不执行游戏。资源包下载以后再做。图片输入只保留“选择图片”，Ctrl+V 继续支持图片及普通文字。

Yume 已采用四种内嵌技能、九个 C# 工具和有限调度。开发者修改项目资源并重新编译，发布版不加载外置技能、DLL 或脚本，不开放用户插件安装/角色编辑；能力更新随应用版本发布。文字会话保存到数据目录 `settings.yume-session`（Windows当前用户加密，最多40条/16万字符，模型历史最多6轮/18000字符）；能力测试、原图、来源卡、待确认操作及撤销记录仍只在内存。历史库事实需重新查询，修改服务/模型/凭据后不恢复旧模型上下文。读取损坏会话不会覆盖原文件，新对话可显式重建。实现边界见 [AI开发文档](ai-integration-development.md)，历史审查结论见 [Yume 升级审查报告](yume-upgrade-audit-2026-09-16.md)。

## 项目结构

```text
src/YumeShelf/
├── Application/      游戏库和启动服务
├── Common/           MVVM 基础类和转换器
├── Domain/           游戏领域模型
├── Infrastructure/  本地文件存储和 Windows 进程启动
├── Presentation/    WPF 主窗口和 ViewModel
└── Resources/       颜色和控件样式
```
