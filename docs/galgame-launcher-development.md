应用正式命名为 **YumeShelf**，内置智能体保持 **Yume**，启动介绍文案为“一个更懂你的游戏盒子...”。本次统一应用品牌、原生图标、侧栏标记和启动页，不改变智能体的服务范围、模型配置或游戏库路径。图标版式、动效与资源维护流程见 [品牌与启动页规范](branding.md)。

AI 子系统以根目录 [Yume 嵌入式专用智能体开发文档](../ai-integration-development.md) v1.12 为统一依据；历史修补与复审见 [Yume 应用契合度报告](../yume-app-integration-audit-2026-09-17.md)。采用现有 C#/.NET/WPF，不新增 Node.js、LangChain 或完整 DSH 运行时。

当前实现四种内嵌技能（角色、识图、库资料、检索）、九个固定工具和有限任务循环。模型负责范围、目标与下一步判断；代码限制参数、真实库 ID、每轮6次模型/4次工具调用、重复请求和期限。角色/技能在源码中维护后重新编译，不扫描外置插件、DLL或脚本；用户仍可自配API地址、Key、对话/视觉模型。

本地库查询：明确的数量/列表整句指令无附件时直接读取当前快照，无需Key、不联网、0模型调用；复杂条件交模型调用library_query，统计/分页结果也由程序生成。每页20项，可按库中记录的类型/引擎/标签/年份筛选，不推断玩法。非快捷执行任务新增一次独立语义核对，计入原6次总预算；general声明不能单独绕过核对要求的本地任务。game_details读取真实字段后由程序直接呈现，避免已读详情被误拒或再次自由编造。介绍/拒绝/首轮澄清仍快速结束；真实供应商语义准确率与新增延迟待验收。

组合任务逐项保留结果；失败/取消/超限显示部分完成和剩余事项，保留原问题。普通追问不覆盖待确认的字段、来源、封面预览、文档和扫描选择；保存/放弃仅消费对应类型，旧同类结果存在时提示先处理，不静默替换。每轮一份修改、一份文档、一份扫描候选，多游戏同类任务仍需分步。可选字段可明确清空并预览/保存/撤销，标题不可清空；扫描按用户完整路径规范化精确比较，拒绝带空格路径的较短前缀。详见AI文档§4.1。

识图修复微信 PNG/透明 DIB 兼容，附图仅随首个视觉请求上传，后续对话模型复用文字线索；选图/预览不联网。设置增加独立视觉与工具协议探测，当前结果只作诊断，非已验证能力驱动的自动模型降级。单次请求默认 60 秒、整任务默认 180 秒；旧 AiTimeoutSeconds 保留为服务/文字测试等待，不重写用户原配置。

AI 页移除手动关联、库访问/联网勾选和独立封面入口，按自然语言任务自动查库定位；用户点名优先，版本歧义澄清。摘要不含启动路径、参数和统计；用户主动输入的路径仍随问题发给模型。联网按任务查询 VNDB 官方 API，无额外Key，显示真实来源，不等于通用网页或反向搜图。

统一修改卡逐项展示原值/新值及封面：复合检索的请求字段默认选中，可取消，模型建议仍默认未选。一次确认提交资料和封面，检查只读、未保存修改、目标删除和版本冲突；失败完整回滚，保留活动Game对象和统计，支持整次撤销。新增发行日期/游戏类型字段兼容旧库，普通编辑器亦可维护。文档可导出MD/安全HTML，尚无GamePages索引。

流式、取消、重试及切页保留会话继续可用；文字会话新增DPAPI本机加密持久化，能力记录、图片、待确认操作和撤销仍只在内存。library_query新增收藏/游玩记录/启动状态组合条件，详细协议以AI文档v1.12为准。真实模型语义/作品识别、逐字段来源验证、Markdown富文本、跨DPI与干净系统发行验收仍待推进。用户未配置AI时离线库功能正常；模型不会自动启动、下载游戏或直接写库。

2026-09-24交付目标：0.3.0-preview.1提供[YumeTestV1真实场景验收](../YumeTestV1.md)供用户执行，开发者并行进行隔离回归、Windows x64自包含封包和仓库同步。[测试包说明](release-guide.md)覆盖解压使用、按用户目录安装、升级/回退、卸载及未验收边界。当前没有签名安装向导或自动更新；干净Win10/Win11验证不以开发机启动替代。

新增prepare_game_update一次取得文字和封面，来源选择后统一预览；find_cover保留为兼容工具，不设独立入口。预览超时保留文字资料；VNDB原文不自动翻译，未知引擎/类型不编造。图片仅写应用数据目录，不改游戏文件。

新增scan_games：用户输入当前本机文件夹/EXE路径，复用现有视觉小说优先/扩展扫描，核对候选后确认入库，沿用去重与保存反馈。拒绝模型虚构路径或扩大到父目录，不执行游戏。资源包下载后置。图片输入仅保留一个选择按钮，Ctrl+V继续支持图片/普通文字。新增技能优先接入对话工具链，不再堆叠常驻操作区。

用户新增协作要求：每次应用修改完成并验证后，正常关闭旧实例、重新构建并启动正式应用，检查窗口响应后交付。同步根目录 AGENTS.md 与开发日志；不丢弃未保存的用户内容。

## 2. 产品目标

YumeShelf 是一个轻量、稳定、偏桌面工具风格的本地 Galgame 游戏库。用户可以把分散在不同硬盘和目录中的游戏统一收纳，查看封面和基本信息，搜索和筛选游戏，并通过一个按钮正确启动游戏。

首版成功标准：

1. 用户可以添加一个游戏目录并选择启动文件。
2. 用户可以在库中搜索、筛选、收藏和选择游戏。
3. 用户点击“启动游戏”后，目标程序以正确的工作目录和启动参数运行。
4. 启动器在游戏运行期间保持可用，游戏退出后记录本次游玩时间。
5. 重启启动器后，游戏条目、封面、设置和游玩记录不丢失。
6. 在没有网络、路径包含中文/日文/空格的情况下仍能正常工作。

## 3. 范围定义

### 3.1 首版包含

- Windows 桌面应用。
- 游戏手动添加。
- 游戏目录、启动 exe、工作目录和启动参数配置。
- 游戏标题、封面、简介、引擎、标签和收藏状态编辑。
- 游戏库封面视图。
- 紧凑列表视图。
- 标题和标签搜索。
- 类型筛选、收藏筛选、最近游玩排序。
- 游戏启动、运行状态识别和游玩时间记录。
- 最近游玩列表。
- 本地 JSON 数据存储；SQLite 作为后续迁移目标。
- 数据库备份和恢复。
- 基础错误提示和日志文件。

### 3.2 首版不包含

- 用户账号和登录。
- 云同步。
- 在线商店、社区和评论。
- 自动下载游戏、补丁或 DLC。
- 自动抓取互联网元数据。
- 游戏内覆盖层。
- 成就系统。
- 多平台支持。
- 自动识别所有游戏引擎。
- 以管理员权限强制启动游戏。

这些功能不是技术上不能做，而是会显著增加隐私、网络、维护和兼容成本。等本地库和启动流程稳定后再评估。

## 4. 产品定位与视觉基线

### 4.1 视觉方向

- Windows 桌面工具感，而不是游戏平台营销页。
- 默认日间白底黑字，灰色分隔线与阴影；单独提供夜间模式。
- 按钮、输入框、下拉框、设置与 AI 页面共用主题资源；夜间区分按钮填充色和强调文字色以保持对比度。
- 自定义背景继续支持预览、模糊和页面内面板透明度；不等同于 Windows 桌面穿透透明。
- 左侧导航、中间库列表、右侧详情三栏结构。
- 封面卡片圆角 14 DIP，封面宽高比 16:9，详情封面采用相同圆角裁剪。
- 信息密度适中，优先保证扫描、搜索和重复启动效率。
- 使用 Segoe UI 和 Microsoft YaHei，保证 Windows 中文显示正常。

### 4.3 响应式行为

虽然首版是 Windows 桌面应用，仍需要处理窗口缩放：

- 默认窗口尺寸：1200 x 760。
- 最小窗口尺寸：900 x 620。
- 宽度小于约 1000px 时，右侧详情面板移动到库列表下方。
- 宽度不足时，左侧导航收缩为图标栏。

## 5. 技术方案

### 5.1 推荐技术栈

| 层 | 选择 | 原因 |
| --- | --- | --- |
| 语言 | C# | Windows 桌面开发成熟，文件、进程和注册表 API 完整 |
| UI | WPF | 适合复杂桌面布局、数据绑定和自定义主题 |
| 架构 | MVVM | 分离界面状态和业务逻辑，便于测试 |
| 运行时 | .NET 8 LTS 或当前受支持 LTS | 生命周期稳定，Windows 部署成熟 |
| 当前持久化 | 本地 JSON 文件 | 首个垂直切片暂不引入第三方数据库依赖，先验证核心流程 |
| 目标持久化 | SQLite | 首版功能稳定后迁移，用于更可靠的查询、迁移和备份 |
| 数据访问 | 当前为 `System.Text.Json`；后续评估 `Microsoft.Data.Sqlite` | 保持依赖最少，避免在核心流程未验证前增加复杂度 |
| 日志 | `Microsoft.Extensions.Logging` + 文件 provider，或轻量自有日志 | 可诊断启动失败和扫描问题 |
| 打包 | MSIX 或自包含发布目录 | 首版先支持可移植目录和安装包二选一 |

### 5.2 依赖原则

- 首版不引入 Unity、Electron 或 WebView。
- 不引入大型 UI 组件库，颜色和控件样式先用 WPF ResourceDictionary 实现。
- 只有当图片格式、缩略图或打包需求确实需要时，再新增库。
- 依赖版本必须锁定，构建必须可重复。

### 5.3 架构边界

```text
View
  ↓ 数据绑定和命令
ViewModel
  ↓ 用例编排
Application Services
  ↓ 业务规则
Domain Models
  ↓ 持久化/进程/文件系统接口
Infrastructure
```

界面层不能直接调用 `Process.Start`、SQLite 或文件扫描。启动、扫描、图片缓存和数据库操作必须通过服务边界进入，避免后续难以测试和处理错误。

## 7. 核心功能设计

### 7.1 游戏添加

设计上计划提供两种添加入口：

1. “添加游戏”：添加一个具体游戏目录。
2. “添加目录”：选择一个父目录，扫描其一级或可配置深度子目录。

当前垂直切片只实现“添加游戏”：用户直接选择一个 `.exe` 文件。父目录扫描入口保留在后续版本，避免把未实现功能伪装成可用功能。

默认流程：

```text
选择目录
  ↓
查找候选启动文件
  ↓
用户确认 exe、标题和工作目录
  ↓
选择封面/填写标签
  ↓
校验路径
  ↓
写入 SQLite
```

启动文件候选规则：

- 优先选择与目录名相近的 exe。
- 排除 `unins*.exe`、`uninstall*.exe`、`crash*.exe`、`setup*.exe` 等明显安装/卸载程序。
- 如果候选超过一个，必须让用户确认。
- 不自动执行扫描到的 exe。
- 不以管理员权限运行扫描或游戏。

### 7.2 游戏信息

必填字段：

- 标题。
- 游戏根目录。
- 启动文件。

可选字段：

- 工作目录，默认是启动文件所在目录或用户指定的根目录。
- 启动参数。
- 封面图片。
- 简介。
- 引擎。
- 发布年份。
- 标签。
- 收藏状态。

### 7.3 游戏启动

启动服务必须完成：

1. 校验启动文件存在且扩展名为 `.exe`。
2. 校验工作目录存在；为空时按规则推导。
3. 使用参数化进程启动 API，不能拼接未经处理的命令字符串。
4. 保存启动时间和进程 ID。
5. 监听目标进程退出。
6. 根据开始和退出时间记录游玩时长。
7. 更新 `LastPlayedAt` 和最近游玩排序。
8. 启动失败时返回用户可理解的错误，并写入详细日志。

进程策略：

- 默认不等待启动器关闭。
- 默认不强制置顶或隐藏启动器。
- 默认只跟踪启动的主进程。
- 不主动杀死游戏进程。
- 游戏崩溃或启动后立即退出时，仍记录实际时长，但标记本次运行结果。

### 7.4 搜索、筛选和视图

- 搜索范围：标题、引擎、标签、简介。
- 搜索为空时显示全部游戏。
- 无结果时显示空状态，不显示空白页面。
- 默认按最近添加或用户上次选择的排序方式展示。
- 封面视图用于浏览；列表视图用于大量游戏的快速扫描。
- 选择游戏后，右侧详情立即更新。
- 删除游戏条目只删除库记录，不删除游戏文件；必须明确提示这一点。

### 7.5 封面和本地资源

- 封面可由用户手动选择，也可通过 Yume 的 VNDB 候选审核后下载；不会静默自动替换。
- 支持常用本地图片格式：PNG、JPG/JPEG、WEBP，具体格式以 WPF 解码能力验证结果为准。
- 手动选图仍保存原路径；联网候选确认后保存为应用数据目录 Covers 下的独立 PNG，库引用本地路径，离线重启仍可展示。
- 图片写入缓存时生成唯一文件名，避免同名覆盖。
- 读取图片失败时显示默认占位封面，并保留原路径错误日志。

## 8. 数据模型

### 8.1 当前数据模型

当前实现将游戏库保存为：

```text
%LOCALAPPDATA%\YumeShelf\library.json
```

文件使用 `System.Text.Json` 序列化 `Game` 集合，要求稳定 ID 与完整 EXE 路径，逐条校验 null、重复身份和字段。最大文件 16 MiB；损坏/读取失败时保留原文件，显示可读部分并暂停正常写入。写入使用独占锁、原快照哈希冲突检测、刷盘的临时文件和替换；正常保存保留 `.bak`，确认恢复保留独立 `.recovery-*.json` 原件。刷新不清除失败修改，退出需重试保存或明确放弃。迁移 SQLite 前必须包含旧数据导入和回滚。

### 8.2 目标 SQLite 模型

```sql
CREATE TABLE Games (
    Id TEXT NOT NULL PRIMARY KEY,
    Title TEXT NOT NULL,
    RootPath TEXT NOT NULL,
    ExecutablePath TEXT NOT NULL,
    WorkingDirectory TEXT NOT NULL,
    LaunchArguments TEXT NOT NULL DEFAULT '',
    Engine TEXT NOT NULL DEFAULT '',
    Description TEXT NOT NULL DEFAULT '',
    ReleaseYear INTEGER NULL,
    CoverPath TEXT NULL,
    IsFavorite INTEGER NOT NULL DEFAULT 0,
    AddedAt TEXT NOT NULL,
    UpdatedAt TEXT NOT NULL,
    LastPlayedAt TEXT NULL,
    TotalPlaySeconds INTEGER NOT NULL DEFAULT 0,
    LastLaunchStatus TEXT NULL
);

CREATE UNIQUE INDEX IX_Games_ExecutablePath ON Games(ExecutablePath);
CREATE INDEX IX_Games_Title ON Games(Title);
CREATE INDEX IX_Games_LastPlayedAt ON Games(LastPlayedAt);
```

### 8.3 Tags 表

```sql
CREATE TABLE Tags (
    Id TEXT NOT NULL PRIMARY KEY,
    Name TEXT NOT NULL UNIQUE
);

CREATE TABLE GameTags (
    GameId TEXT NOT NULL,
    TagId TEXT NOT NULL,
    PRIMARY KEY (GameId, TagId),
    FOREIGN KEY (GameId) REFERENCES Games(Id) ON DELETE CASCADE,
    FOREIGN KEY (TagId) REFERENCES Tags(Id) ON DELETE CASCADE
);
```

### 8.4 PlaySessions 表

```sql
CREATE TABLE PlaySessions (
    Id TEXT NOT NULL PRIMARY KEY,
    GameId TEXT NOT NULL,
    StartedAt TEXT NOT NULL,
    EndedAt TEXT NULL,
    DurationSeconds INTEGER NOT NULL DEFAULT 0,
    ProcessId INTEGER NULL,
    Status TEXT NOT NULL,
    FOREIGN KEY (GameId) REFERENCES Games(Id) ON DELETE CASCADE
);
```

时间统一保存为带时区的 ISO 8601 字符串；展示时转换为本地时间。

### 8.5 应用数据目录

建议使用 Windows 的本地应用数据目录：

```text
%LOCALAPPDATA%\YumeShelf\
├── library.json       当前阶段
├── yumeshelf.db       SQLite 迁移后
├── covers\
├── backups\
└── logs\
```

不要把数据库和封面写入安装目录，也不要把用户的游戏目录作为应用配置目录。

## 9. 引擎兼容策略

首版以“可配置启动器”为核心，不为每种引擎写复杂插件。引擎字段主要用于展示、筛选和后续诊断。

| 引擎 | 首版策略 | 备注 |
| --- | --- | --- |
| Ren'Py | 直接启动 Windows exe，工作目录指向游戏目录 | 通常兼容性最好 |
| Unity | 启动主 exe，工作目录为 exe 所在目录 | 支持启动参数 |
| TyranoScript/Builder | 按导出的 exe 处理 | 不依赖编辑器运行 |
| Kirikiri/KAG | 手动选择 exe 和参数 | 可能受区域设置、编码和插件影响 |
| RPG Maker | 按导出的 exe 或启动脚本处理 | 首版不自动推导特殊启动方式 |
| 未知引擎 | 用户手动配置 | 保证基础启动能力 |

需要特殊兼容时，新增“启动配置策略”而不是在 UI 中堆叠引擎特判：

```text
LaunchProfile
- ExecutablePath
- WorkingDirectory
- Arguments
- EnvironmentVariables（后续）
- LocaleMode（后续）
- WaitForChildProcess（后续）
```

- 主窗口右上角显示统一圆角提示卡，覆盖游戏库、设置和 AI 页面，切换导航不隐藏结果；添加窗口拥有自己的提示区域。提示不抢焦点，不阻塞下一步操作，适配日间/夜间主题与窄窗口。
- 成功和普通提示显示 4 秒后自动关闭；重复点击同一操作会重新显示并重新计时。鼠标悬停或键盘焦点进入提示时暂停计时。错误、警告及处理中提示保留到下一条结果或手动关闭。
- 按钮点击不等于成功：设置保存/应用完成、游戏库写入完成后才能显示成功。选择背景或恢复默认先显示“预览，确认后应用”；继续修改设置时底部显示未保存，保存失败时清除过时的成功状态并保留草稿。
- 游戏添加返回成功、重复或失败的明确结果。批量确认汇总本窗口累计添加数及本次重复/失败数，部分失败留在添加窗口供检查与重试；没有勾选时说明原因。扫描开始、扫描完成、无结果和失败均有反馈，扫描期间禁用重复提交及修改搜索范围。
- 编辑、收藏、移除、刷新、启动、游戏退出记录和打开目录均提供相应结果；取消与成功使用不同文案。移除仅在持久化成功后更新列表，并明确游戏文件未删除。
- 游戏库编辑或游玩状态写入失败时保留当前内存修改，提示中提供“重新保存”；此时禁止刷新覆盖未保存数据。新增/移除先写入待保存快照，失败时维持原列表。刷新读取损坏数据失败时保留当前列表并提示，不显示“刷新成功”。
- API 服务/模型测试显示处理中及结果；AI 缺少配置、请求失败、超时和停止均有明确提示且保留问题。正常回复本身作为完成反馈，不额外弹出成功提示。错误只显示可操作摘要，不展示 Key 或原始服务响应。
- 搜索、筛选、视图切换及滑块预览通过页面即时变化反馈，不为每次输入或拖动叠加提示。移除确认及编辑字段校验保留现有确认/校验交互。

## 11. 错误处理与安全要求

### 11.1 用户可见错误

错误提示需要说明：发生了什么、用户可以做什么。例：

```text
无法启动游戏
找不到启动文件：D:\Galgames\Example\game.exe
请编辑该游戏条目，重新选择启动文件。
```

不要直接把异常堆栈显示给用户；堆栈写入日志。

### 11.2 文件系统安全

- 使用 `Path.GetFullPath` 规范化路径。
- 使用 `File.Exists` 和 `Directory.Exists` 做启动前校验。
- 不执行用户未确认的扫描结果。
- 不删除游戏目录和游戏文件。
- 删除库条目时只操作 SQLite 和应用缓存。
- 复制封面时限制文件大小，避免一次性加载异常大图片。
- 数据库写入使用参数化 SQL。

### 11.3 进程安全

- 不默认提权。
- 不拼接 `cmd.exe /c` 命令。
- 使用 `ProcessStartInfo.FileName` 和 `ArgumentList` 或安全的参数传递机制。
- 进程启动失败、权限不足、文件被占用都要被捕获并记录。

## 12. 状态设计

游戏条目状态：

```text
Unknown      未验证
Available    启动文件存在，可启动
Missing      启动文件或目录不存在
Running      已启动且进程仍在运行
Broken       最近一次启动失败
```

页面状态：

- Loading：加载数据库或扫描目录。
- Ready：正常展示。
- Empty：没有添加游戏。
- NoResults：搜索无结果。
- Error：数据库或文件系统异常。
- Confirming：用户正在确认添加、删除或恢复操作。

这些状态必须在 ViewModel 中明确表达，不能只靠按钮是否可用来猜测。

## 13. 日志与诊断

日志目录：

```text
%LOCALAPPDATA%\YumeShelf\logs\
```

记录内容：

- 应用启动和版本。
- 数据库迁移结果。
- 游戏扫描数量和耗时。
- 启动目标、工作目录和参数摘要。
- 进程启动成功/失败。
- 游戏退出状态和游玩时长。
- 图片复制失败。
- 未处理异常。

不要记录密码、用户账号或不必要的游戏文件内容。启动参数可能包含敏感信息时，日志只记录参数是否存在和长度，不记录原文。

## 19. 本地测试程序

项目内新增 `tests/YumeShelf.TestGame`，用于验证启动器的进程启动闭环，不依赖真实游戏。

测试程序支持：

- `--duration <秒>`：设置运行时间，范围为 1-300 秒，默认 10 秒。
- 其他参数：原样写入测试报告，便于检查启动参数是否传递。
- 启动时在当前工作目录生成 `test-game-run.log`，记录启动时间、进程 ID、工作目录和参数。
- 到时自动正常退出，便于验证启动器的进程退出监听和游玩时长累计。

构建后可将以下文件作为普通游戏添加到 YumeShelf：

```text
tests\\YumeShelf.TestGame\\bin\\Debug\\net8.0-windows\\YumeShelf.TestGame.exe
```

建议测试配置：

```text
启动参数：--duration 15 --profile 中文路径测试
工作目录：测试程序 exe 所在目录
```

## 20. 当前可运行状态（2026-09-15）

自动模式允许选择磁盘或文件夹，提供“视觉小说优先”和“扩展游戏扫描”。默认模式保留视觉小说筛选；扩展模式接受具有游戏资源结构的 RPG Maker、WOLF RPG、Unity 和 GameMaker 候选，无需日文、汉化或已有存档。视觉小说专用入口默认勾选，通用游戏和未知引擎候选显示“待确认”且不预选；两种模式都必须点击确认添加后才入库。手动模式继续选择 EXE，使用同一套引擎标注。

扫描上限为 12 层、10000 目录、500 候选、每目录 4096 个枚举项与 60 秒软期限；PFS/YPF 每类资源每目录最多检查 32 个文件头。达到上限、资源不可读或跳过无权限/链接目录时报告不完整。脚本/背景/语音与同名 BIN 配对保留原识别；Unity 按 EXE 对应的 `_Data` 目录匹配，避免同目录辅助 EXE 借用其他游戏的资源。

当前新增覆盖 RPG Maker 2000/2003、XP、VX、VX Ace、MV、MZ 的常见 Windows 导出结构，WOLF RPG，以及 NScripter/ONScripter、RealLive、Siglus、Artemis、YU-RIS。详细矩阵、筛选条件、启动入口选择和未覆盖版本见 [游戏扫描说明](game-scanning.md)。引擎与玩法分开，识别不自动写入 ACT/SLG/RPG 分类，也不改变 Yume 智能体的 Galgame 服务范围。

添加窗口内两种添加方式保留等高表单，模式选择沿用主题下拉控件；结果路径省略并可悬停查看全文，依据自动换行，列表独立滚动、底部按钮固定。切换目录或扫描模式清空旧候选和反馈，“重新扫描”替换旧结果；扫描/导入期间冻结模式、选择和提交按钮。
