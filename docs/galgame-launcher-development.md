## 2. 产品目标

YumeShelf 是一个轻量、稳定、偏桌面工具风格的本地 Galgame 游戏库。用户可以把分散在不同硬盘和目录中的游戏统一收纳，查看封面和基本信息，搜索和筛选游戏，并通过一个按钮正确启动游戏。

首版成功标准：

1. 用户可以添加一个游戏目录并选择启动文件。
2. 用户可以在库中搜索、筛选、收藏和选择游戏。
3. 用户点击“启动游戏”后，目标程序以正确的工作目录和启动参数运行。
4. 启动器在游戏运行期间保持可用，游戏退出后记录本次游玩时间。
5. 重启启动器后，游戏条目、封面、设置和游玩记录不丢失。
6. 在没有网络、路径包含中文/日文/空格的情况下仍能正常工作。

## 3. 范围定义

### 3.1 首版包含

- Windows 桌面应用。
- 游戏手动添加。
- 游戏目录、启动 exe、工作目录和启动参数配置。
- 游戏标题、封面、简介、引擎、标签和收藏状态编辑。
- 游戏库封面视图。
- 紧凑列表视图。
- 标题和标签搜索。
- 类型筛选、收藏筛选、最近游玩排序。
- 游戏启动、运行状态识别和游玩时间记录。
- 最近游玩列表。
- 本地 JSON 数据存储；SQLite 作为后续迁移目标。
- 数据库备份和恢复。
- 基础错误提示和日志文件。

### 3.2 首版不包含

- 用户账号和登录。
- 云同步。
- 在线商店、社区和评论。
- 自动下载游戏、补丁或 DLC。
- 自动抓取互联网元数据。
- 游戏内覆盖层。
- 成就系统。
- 多平台支持。
- 自动识别所有游戏引擎。
- 以管理员权限强制启动游戏。

这些功能不是技术上不能做，而是会显著增加隐私、网络、维护和兼容成本。等本地库和启动流程稳定后再评估。

## 5. 技术方案

### 5.1 推荐技术栈

| 层 | 选择 | 原因 |
| --- | --- | --- |
| 语言 | C# | Windows 桌面开发成熟，文件、进程和注册表 API 完整 |
| UI | WPF | 适合复杂桌面布局、数据绑定和自定义主题 |
| 架构 | MVVM | 分离界面状态和业务逻辑，便于测试 |
| 运行时 | .NET 8 LTS 或当前受支持 LTS | 生命周期稳定，Windows 部署成熟 |
| 当前持久化 | 本地 JSON 文件 | 首个垂直切片暂不引入第三方数据库依赖，先验证核心流程 |
| 目标持久化 | SQLite | 首版功能稳定后迁移，用于更可靠的查询、迁移和备份 |
| 数据访问 | 当前为 `System.Text.Json`；后续评估 `Microsoft.Data.Sqlite` | 保持依赖最少，避免在核心流程未验证前增加复杂度 |
| 日志 | `Microsoft.Extensions.Logging` + 文件 provider，或轻量自有日志 | 可诊断启动失败和扫描问题 |
| 打包 | MSIX 或自包含发布目录 | 首版先支持可移植目录和安装包二选一 |

### 5.2 依赖原则

- 首版不引入 Unity、Electron 或 WebView。
- 不引入大型 UI 组件库，颜色和控件样式先用 WPF ResourceDictionary 实现。
- 只有当图片格式、缩略图或打包需求确实需要时，再新增库。
- 依赖版本必须锁定，构建必须可重复。

### 5.3 架构边界

```text
View
  ↓ 数据绑定和命令
ViewModel
  ↓ 用例编排
Application Services
  ↓ 业务规则
Domain Models
  ↓ 持久化/进程/文件系统接口
Infrastructure
```

界面层不能直接调用 `Process.Start`、SQLite 或文件扫描。启动、扫描、图片缓存和数据库操作必须通过服务边界进入，避免后续难以测试和处理错误。

## 7. 核心功能设计

### 7.1 游戏添加

设计上计划提供两种添加入口：

1. “添加游戏”：添加一个具体游戏目录。
2. “添加目录”：选择一个父目录，扫描其一级或可配置深度子目录。

当前垂直切片只实现“添加游戏”：用户直接选择一个 `.exe` 文件。父目录扫描入口保留在后续版本，避免把未实现功能伪装成可用功能。

默认流程：

```text
选择目录
  ↓
查找候选启动文件
  ↓
用户确认 exe、标题和工作目录
  ↓
选择封面/填写标签
  ↓
校验路径
  ↓
写入 SQLite
```

启动文件候选规则：

- 优先选择与目录名相近的 exe。
- 排除 `unins*.exe`、`uninstall*.exe`、`crash*.exe`、`setup*.exe` 等明显安装/卸载程序。
- 如果候选超过一个，必须让用户确认。
- 不自动执行扫描到的 exe。
- 不以管理员权限运行扫描或游戏。

### 7.2 游戏信息

必填字段：

- 标题。
- 游戏根目录。
- 启动文件。

可选字段：

- 工作目录，默认是启动文件所在目录或用户指定的根目录。
- 启动参数。
- 封面图片。
- 简介。
- 引擎。
- 发布年份。
- 标签。
- 收藏状态。

### 7.3 游戏启动

启动服务必须完成：

1. 校验启动文件存在且扩展名为 `.exe`。
2. 校验工作目录存在；为空时按规则推导。
3. 使用参数化进程启动 API，不能拼接未经处理的命令字符串。
4. 保存启动时间和进程 ID。
5. 监听目标进程退出。
6. 根据开始和退出时间记录游玩时长。
7. 更新 `LastPlayedAt` 和最近游玩排序。
8. 启动失败时返回用户可理解的错误，并写入详细日志。

进程策略：

- 默认不等待启动器关闭。
- 默认不强制置顶或隐藏启动器。
- 默认只跟踪启动的主进程。
- 不主动杀死游戏进程。
- 游戏崩溃或启动后立即退出时，仍记录实际时长，但标记本次运行结果。

### 7.4 搜索、筛选和视图

- 搜索范围：标题、引擎、标签、简介。
- 搜索为空时显示全部游戏。
- 无结果时显示空状态，不显示空白页面。
- 默认按最近添加或用户上次选择的排序方式展示。
- 封面视图用于浏览；列表视图用于大量游戏的快速扫描。
- 选择游戏后，右侧详情立即更新。
- 删除游戏条目只删除库记录，不删除游戏文件；必须明确提示这一点。

### 7.5 封面和本地资源

- 封面由用户手动选择，首版不自动联网下载。
- 支持常用本地图片格式：PNG、JPG/JPEG、WEBP，具体格式以 WPF 解码能力验证结果为准。
- 当前保存用户选择的封面路径；复制到应用数据目录的缓存方案留到后续版本。
- 图片写入缓存时生成唯一文件名，避免同名覆盖。
- 读取图片失败时显示默认占位封面，并保留原路径错误日志。

## 8. 数据模型

### 8.1 当前数据模型

当前实现将游戏库保存为：

```text
%LOCALAPPDATA%\YumeShelf\library.json
```

文件使用 `System.Text.Json` 序列化 `Game` 对象集合，并采用临时文件替换方式保存。迁移 SQLite 前必须先写入版本化迁移策略，并为已有 JSON 数据提供一次性导入；不得直接删除 JSON 数据。

### 8.2 目标 SQLite 模型

```sql
CREATE TABLE Games (
    Id TEXT NOT NULL PRIMARY KEY,
    Title TEXT NOT NULL,
    RootPath TEXT NOT NULL,
    ExecutablePath TEXT NOT NULL,
    WorkingDirectory TEXT NOT NULL,
    LaunchArguments TEXT NOT NULL DEFAULT '',
    Engine TEXT NOT NULL DEFAULT '',
    Description TEXT NOT NULL DEFAULT '',
    ReleaseYear INTEGER NULL,
    CoverPath TEXT NULL,
    IsFavorite INTEGER NOT NULL DEFAULT 0,
    AddedAt TEXT NOT NULL,
    UpdatedAt TEXT NOT NULL,
    LastPlayedAt TEXT NULL,
    TotalPlaySeconds INTEGER NOT NULL DEFAULT 0,
    LastLaunchStatus TEXT NULL
);

CREATE UNIQUE INDEX IX_Games_ExecutablePath ON Games(ExecutablePath);
CREATE INDEX IX_Games_Title ON Games(Title);
CREATE INDEX IX_Games_LastPlayedAt ON Games(LastPlayedAt);
```

### 8.3 Tags 表

```sql
CREATE TABLE Tags (
    Id TEXT NOT NULL PRIMARY KEY,
    Name TEXT NOT NULL UNIQUE
);

CREATE TABLE GameTags (
    GameId TEXT NOT NULL,
    TagId TEXT NOT NULL,
    PRIMARY KEY (GameId, TagId),
    FOREIGN KEY (GameId) REFERENCES Games(Id) ON DELETE CASCADE,
    FOREIGN KEY (TagId) REFERENCES Tags(Id) ON DELETE CASCADE
);
```

### 8.4 PlaySessions 表

```sql
CREATE TABLE PlaySessions (
    Id TEXT NOT NULL PRIMARY KEY,
    GameId TEXT NOT NULL,
    StartedAt TEXT NOT NULL,
    EndedAt TEXT NULL,
    DurationSeconds INTEGER NOT NULL DEFAULT 0,
    ProcessId INTEGER NULL,
    Status TEXT NOT NULL,
    FOREIGN KEY (GameId) REFERENCES Games(Id) ON DELETE CASCADE
);
```

时间统一保存为带时区的 ISO 8601 字符串；展示时转换为本地时间。

### 8.5 应用数据目录

建议使用 Windows 的本地应用数据目录：

```text
%LOCALAPPDATA%\YumeShelf\
├── library.json       当前阶段
├── yumeshelf.db       SQLite 迁移后
├── covers\
├── backups\
└── logs\
```

不要把数据库和封面写入安装目录，也不要把用户的游戏目录作为应用配置目录。

## 9. 引擎兼容策略

首版以“可配置启动器”为核心，不为每种引擎写复杂插件。引擎字段主要用于展示、筛选和后续诊断。

| 引擎 | 首版策略 | 备注 |
| --- | --- | --- |
| Ren'Py | 直接启动 Windows exe，工作目录指向游戏目录 | 通常兼容性最好 |
| Unity | 启动主 exe，工作目录为 exe 所在目录 | 支持启动参数 |
| TyranoScript/Builder | 按导出的 exe 处理 | 不依赖编辑器运行 |
| Kirikiri/KAG | 手动选择 exe 和参数 | 可能受区域设置、编码和插件影响 |
| RPG Maker | 按导出的 exe 或启动脚本处理 | 首版不自动推导特殊启动方式 |
| 未知引擎 | 用户手动配置 | 保证基础启动能力 |

需要特殊兼容时，新增“启动配置策略”而不是在 UI 中堆叠引擎特判：

```text
LaunchProfile
- ExecutablePath
- WorkingDirectory
- Arguments
- EnvironmentVariables（后续）
- LocaleMode（后续）
- WaitForChildProcess（后续）
```

## 10. 界面与交互规格

### 10.1 导航

左侧导航项目：

- 全部游戏：显示全部有效游戏条目。
- 最近游玩：按 `LastPlayedAt` 降序。
- 收藏：只显示 `IsFavorite = true`。
- 添加目录：打开目录选择和扫描流程。
- 设置：打开本地路径、主题和数据管理设置。

### 10.2 主操作

- “添加游戏”是主按钮，橙色填充。
- “启动游戏”是详情面板的主按钮，橙色填充。
- 删除、编辑、打开目录等是次级操作。
- 纯图标按钮必须有可见的悬停提示和无障碍名称。
- 操作按钮不能因为标题过长而改变布局尺寸。

### 10.3 添加游戏对话框

字段顺序：

1. 游戏目录。
2. 启动文件。
3. 工作目录。
4. 标题。
5. 启动参数。
6. 封面。
7. 引擎。
8. 标签。
9. 简介。

校验：

- 目录不存在：阻止保存。
- exe 不存在：阻止保存。
- exe 不在游戏根目录下：允许保存，但显示确认提示。
- 已存在相同 exe：阻止重复添加。
- 标题为空：阻止保存。

### 10.4 设置

设置嵌入主窗口右侧，保留左侧主导航；设置页面内再按左侧分类、右侧内容、底部固定确认区排列。AI 助手同样嵌入右侧，两者都不创建独立子窗口。当前设置分类：

| 分类 | 当前行为 |
| --- | --- |
| 应用美化 | 图片预览、选择图片、恢复默认、页面透明度和高斯模糊 |
| AI 检索 | API 地址、掩码 Key、模型、超时，以及独立的服务连通检查和模型回答测试；联网检索和资料补全按 AI 开发基线继续推进 |
| 页面分栏 | 简化页面 / 完整页面，可切换并保存 |

页面随主窗口右侧剩余空间伸缩；主窗口默认 1200 × 760，最小 900 × 620。内容区域允许纵向滚动，底部“取消”“确认并保存”始终可见。分类选中状态明确显示，切换分类或主导航均保留当前草稿。

应用美化规格：

- 使用图片内容和文件名作为预览，不再用文件地址文本框作为主要界面。
- 主窗口搜索框固定为 340px，包含搜索图标、明确占位文字和仅在有搜索内容时出现的清空按钮；输入即时筛选标题、引擎、标签和简介。
- 游戏类型筛选使用自定义下拉控件，浅色显示区与搜索框统一，展开菜单使用深色面板、圆角、悬停和选中高亮，避免系统默认白色菜单破坏页面层次。
- 每个游戏条目卡片都提供“编辑”和“移除”按钮：封面卡片放在底部，紧凑列表放在行尾；右侧详情区不重复显示这两个操作，避免用户寻找条目级操作时产生歧义。
- 选择图片时先解码验证，损坏或不可读的图片显示错误并保留上一次有效预览。
- 页面透明度为 0%–100%，控制左侧导航、中间游戏库和右侧详情面板的透明程度，让背景图透出；0% 为不透明，100% 为较高透明度。文字、按钮和封面内容保持自身清晰度，不改变整个 Windows 窗口的系统级透明度。
- 高斯模糊半径为 0–30 px，仅作用于背景图片；滑块调整在设置预览中实时可见。
- PNG、JPG/JPEG、BMP、GIF 由 WPF 解码，GIF 仅显示静态帧。图片解码宽度限制为 1920 像素并在加载完成后释放源文件句柄。
- 选择、清除、拖动滑块、切换布局只修改页面草稿；主导航切页保留草稿，“取消”恢复已保存的配置并留在当前分类，关闭应用丢弃未保存草稿。嵌入页不注册窗口级默认/取消按钮，避免 Enter 或 Esc 误触主窗口行为。
- “确认并保存”重新验证图片，成功保存后更新主窗口并留在设置页显示成功状态；失败时显示错误并保留草稿。API 配置从下一次 AI 请求生效，不重建会话或改变进行中请求的配置。
- 简化页面隐藏右侧详情栏，底部保留启动、编辑、收藏、打开目录和移除操作；完整页面保留原有三栏结构。

### 10.6 统一操作反馈（2026-09-15）

- 主窗口右上角显示统一圆角提示卡，覆盖游戏库、设置和 AI 页面，切换导航不隐藏结果；添加窗口拥有自己的提示区域。提示不抢焦点，不阻塞下一步操作，适配日间/夜间主题与窄窗口。
- 成功和普通提示显示 4 秒后自动关闭；重复点击同一操作会重新显示并重新计时。鼠标悬停或键盘焦点进入提示时暂停计时。错误、警告及处理中提示保留到下一条结果或手动关闭。
- 按钮点击不等于成功：设置保存/应用完成、游戏库写入完成后才能显示成功。选择背景或恢复默认先显示“预览，确认后应用”；继续修改设置时底部显示未保存，保存失败时清除过时的成功状态并保留草稿。
- 游戏添加返回成功、重复或失败的明确结果。批量确认汇总本窗口累计添加数及本次重复/失败数，部分失败留在添加窗口供检查与重试；没有勾选时说明原因。扫描开始、扫描完成、无结果和失败均有反馈，扫描期间禁用重复提交及修改搜索范围。
- 编辑、收藏、移除、刷新、启动、游戏退出记录和打开目录均提供相应结果；取消与成功使用不同文案。移除仅在持久化成功后更新列表，并明确游戏文件未删除。

- API 服务/模型测试显示处理中及结果；AI 缺少配置、请求失败、超时和停止均有明确提示且保留问题。正常回复本身作为完成反馈，不额外弹出成功提示。错误只显示可操作摘要，不展示 Key 或原始服务响应。
- 搜索、筛选、视图切换及滑块预览通过页面即时变化反馈，不为每次输入或拖动叠加提示。移除确认及编辑字段校验保留现有确认/校验交互。

## 11. 错误处理与安全要求

### 11.1 用户可见错误

错误提示需要说明：发生了什么、用户可以做什么。例：

```text
无法启动游戏
找不到启动文件：D:\Galgames\Example\game.exe
请编辑该游戏条目，重新选择启动文件。
```

不要直接把异常堆栈显示给用户；堆栈写入日志。

### 11.2 文件系统安全

- 使用 `Path.GetFullPath` 规范化路径。
- 使用 `File.Exists` 和 `Directory.Exists` 做启动前校验。
- 不执行用户未确认的扫描结果。
- 不删除游戏目录和游戏文件。
- 删除库条目时只操作 SQLite 和应用缓存。
- 复制封面时限制文件大小，避免一次性加载异常大图片。
- 数据库写入使用参数化 SQL。

### 11.3 进程安全

- 不默认提权。
- 不拼接 `cmd.exe /c` 命令。
- 使用 `ProcessStartInfo.FileName` 和 `ArgumentList` 或安全的参数传递机制。
- 进程启动失败、权限不足、文件被占用都要被捕获并记录。

## 12. 状态设计

游戏条目状态：

```text
Unknown      未验证
Available    启动文件存在，可启动
Missing      启动文件或目录不存在
Running      已启动且进程仍在运行
Broken       最近一次启动失败
```

页面状态：

- Loading：加载数据库或扫描目录。
- Ready：正常展示。
- Empty：没有添加游戏。
- NoResults：搜索无结果。
- Error：数据库或文件系统异常。
- Confirming：用户正在确认添加、删除或恢复操作。

这些状态必须在 ViewModel 中明确表达，不能只靠按钮是否可用来猜测。

## 13. 日志与诊断

日志目录：

```text
%LOCALAPPDATA%\YumeShelf\logs\
```

记录内容：

- 应用启动和版本。
- 数据库迁移结果。
- 游戏扫描数量和耗时。
- 启动目标、工作目录和参数摘要。
- 进程启动成功/失败。
- 游戏退出状态和游玩时长。
- 图片复制失败。
- 未处理异常。

不要记录密码、用户账号或不必要的游戏文件内容。启动参数可能包含敏感信息时，日志只记录参数是否存在和长度，不记录原文。
